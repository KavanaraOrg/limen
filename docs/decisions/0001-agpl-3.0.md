# 0001: limen is licensed under AGPL-3.0

**Status:** Accepted
**Date:** 2026-11-22
**Deviates from:** the Apache-2.0 default of `ADR-0008-sbom-and-commercial-use`,
which requires another licence to be a decision recorded in the repository.
This is that record.

## Decision

limen is licensed under the GNU Affero General Public License v3.0
(AGPL-3.0-only), copyright Kavanara GmbH. Releases up to and including 0.18.0
were published under Apache-2.0 and remain available under it.

## Why this satisfies ADR-0008

- **Commercial use is allowed.** ADR-0008 requires the repository's own licence
  to allow commercial use. AGPL-3.0 does; it requires that a modified version
  distributed or offered over a network is made available with its source
  under the same licence.
- **The copyright holder is not bound.** Kavanara GmbH holds the copyright and
  can use limen in its own products on any terms.
- **Other KavanaraOrg projects are not affected.** They run limen as a separate
  program next to their own code (a shell hook, a CLI call, the WezTerm
  module). That is aggregation, which ADR-0008 lists but does not gate by the
  copyleft classes. No project links or bundles limen's Go code.

## Consequences

- A third party that changes limen and distributes it, or offers it over a
  network, has to publish its changes.
- A project that wants to import limen's Go packages as a library would trip
  its own ADR-0008 gate on AGPL. Should that be needed, Kavanara GmbH can
  dual-license, or the code in question moves into a permissively licensed
  module.
